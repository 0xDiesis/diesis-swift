**The Swift SDK for Diesis**

Call the Diesis system contracts from Swift with typed parameter, event,
error, and tuple structs, selectors and event topics, every system address as
a constant, and a contract table that hands you a ready
[web3swift](https://github.com/web3swift-team/web3swift) contract object.

Chain ID `1980` · Token **DS** · Runtime **web3swift 3** · Swift **5.9+** · macOS **13+** · iOS **16+**

_Greek δίεσις: the smallest interval in music.<br>Diesis aims for the smallest interval between blocks._

</div>

---

## Why this SDK

Diesis builds trading, fee sponsorship, names, staking, and private transfers
into the chain itself, behind system contracts at fixed addresses. This
package gives an iOS or macOS app those addresses, ABIs, and Swift types, so
you don't copy hex strings or ABI files by hand.

- `DiesisContracts` pairs each of the 28 fixed-address contracts with its
  address and ABI, using the same keys as the
  [TypeScript SDK](https://github.com/0xDiesis/diesis-js)'s `diesisContracts`.
- The ABI, selectors, event topics, and parameter, event, error, and tuple
  structs for all 29 public contracts are generated by abi-typegen from the
  Solidity build.
- Addresses and chain data are generated from the same `canonical.json` as the
  TypeScript and [Python](https://github.com/0xDiesis/diesis-py) SDKs.

## Install

The package is not in a registry yet. Add it from GitHub with authenticated
Git access, and pin a commit so builds stay reproducible:

```swift
// Package.swift
dependencies: [
    .package(url: "https://github.com/0xDiesis/diesis-swift.git", revision: "<commit>"),
],
targets: [
    .target(name: "App", dependencies: [.product(name: "Diesis", package: "diesis-swift")]),
]
```

The package depends on web3swift 3.3.2 or later within 3.x, and on BigInt 5.4
or later within 5.x. Import `web3swift` and `Web3Core` next to `Diesis`, since
`EthereumAddress` and the keystore types live in `Web3Core`.

## Connect

**In short.** You make a web3swift `Web3` object that points at a Diesis
node. Everything else in this README uses it.

**Details.** `DiesisChain.diesis` and `DiesisChain.diesisTestnet` carry the
chain ID, name, native currency, RPC URL, and explorer URL. `chain.network`
is the web3swift `Networks` value for the chain ID. Passing it to
`Web3HttpProvider` skips the chain ID request on connect.

```swift
import Diesis
import Web3Core
import web3swift

let chain = DiesisChain.diesisTestnet
let provider = try await Web3HttpProvider(url: chain.rpcURL, network: chain.network)
let web3 = Web3(provider: provider)

let blockNumber = try await web3.eth.blockNumber()  // plain web3swift still works
```

| Network        | Chain ID | Constant                    |
| -------------- | -------- | --------------------------- |
| Diesis Mainnet | 1980     | `DiesisChain.diesis`        |
| Diesis Testnet | 19803    | `DiesisChain.diesisTestnet` |

## Read a value

**In short.** You pick a contract from the table, name the function, and pass
its arguments. The node runs the call and returns the result without a
transaction.

**Details.** `web3.contract(DiesisContracts.staking)` returns a
`Web3.Contract` bound to the staking contract's fixed address, or `nil` if
web3swift can't parse the ABI. web3swift takes arguments as an untyped
`[Any]` array, so build them from the generated `Params` struct to get the
names and Swift types checked by the compiler. Results come back keyed by
output name, or by position (`"0"`) for unnamed outputs.

```swift
import BigInt

let staking = web3.contract(DiesisContracts.staking)!

let params = DiesisStaking.UnclaimedRewardsParams(tokenId: 42)
let result = try await staking
    .createReadOperation("unclaimedRewards", parameters: [params.tokenId])!
    .callContractMethod()
let rewards = result["0"] as? BigUInt
```

## Send a transaction

**In short.** You give web3swift your key, build the call the same way as a
read, and send it. The key stays on the device and signs locally.

**Details.** Attach a `KeystoreManager` to `web3`, then set `from` and, for
payable functions, `value` on the operation's transaction. `writeToChain`
fills in the nonce, gas, and fees, signs, and sends. The password is the
keystore password, which is empty for a `PlainKeystore`.

```swift
let keystore = PlainKeystore(privateKey: privateKey)!
web3.addKeystoreManager(KeystoreManager([keystore]))
let sender = keystore.addresses!.first!

let staking = web3.contract(DiesisContracts.staking)!
let params = DiesisStaking.StakeParams(toValidatorId: 1)
let operation = staking.createWriteOperation("stake", parameters: [params.toValidatorId])!
operation.transaction.from = sender
operation.transaction.value = Utilities.parseToBigUInt("100", units: .ether)!

let sent = try await operation.writeToChain(password: "")
print(sent.hash)
```

## Addresses and the contract table

**In short.** Diesis system contracts live at fixed addresses that start with
`0xD1E515`. The SDK has all of them as `EthereumAddress` constants, plus the
ABI for each public contract.

**Details.** `DiesisAddresses` has one constant per entry in
`canonical.json`, in lower camel case (`DIESIS_SPOT_BOOK` becomes
`diesisSpotBook`), and `DiesisAddresses.all` keys them by the original name.
`DiesisContracts` has one `DiesisContract` per fixed-address contract, with
`key`, `name`, `address`, and `abi`.

Each of the 29 public contracts also has a generated enum with its own name,
including `IValidatorShare`, which has one address per validator instead of a
fixed one. The enum holds the ABI JSON (`abi`), the canonical signature and
selector of each function and error, the signature and topic 0 of each
event, and public `Sendable`, `Hashable` structs nested inside it, such as
`DiesisStaking.StakeParams`, `DiesisStaking.StakedEvent`,
`IWrappedDS.InsufficientBalanceError`, and the Solidity struct
`IDiesisErc20Factory.DeployParams`.

```swift
let spotBook = DiesisAddresses.diesisSpotBook
let multicall = DiesisAddresses.multicall3

for entry in DiesisContracts.all {
    print(entry.key, entry.name, entry.address.address)
}

let share = web3.contract(IValidatorShare.abi, at: shareAddress)!
let stakeSelector = DiesisStaking.stakeSelector  // Data([0xa6, 0x94, 0xfc, 0x3a])
```

`canonical.json` in the repo root is the same address and chain data as
JSON, for tools that don't run Swift.

## Regenerate

**In short.** One script rebuilds every generated file from the Solidity
build and `canonical.json`. A check mode tells you if anything is stale.

**Details.** `scripts/generate.py` uses only the Python standard library. It
runs abi-typegen's Swift target into a temporary directory and writes its
output unchanged to `Sources/Diesis/Generated/`. It copies
`../diesis-js/canonical.json` into the repo and generates `Addresses.swift`,
`Chains+Generated.swift`, and `Contracts+Generated.swift` from it. `--check` writes nothing and exits non-zero if any of
those files, or the vendored `canonical.json`, differs from what it would
produce.

```bash
python3 scripts/generate.py          # regenerate
python3 scripts/generate.py --check  # fail if anything is stale
```

The contracts checkout defaults to `../../diesis-core/diesis/contracts` with compiled
artifacts in `out/`. Set `DIESIS_CONTRACTS_DIR` to use another checkout, and
`ABI_TYPEGEN` to use another abi-typegen binary than
`<contracts>/node_modules/.bin/abi-typegen`. The script needs abi-typegen
0.8.0 or later and stops with an error on an older one.

## Develop

```bash
swift build
swift test
```

The tests check the addresses and chains against `canonical.json`, parse every
ABI with web3swift, compare each generated ABI with the compiled artifact
(skipped when the contracts checkout is missing), check the contract table and
the generated selectors, and encode calls from the generated structs. `Tests/DiesisTests/ReadmeExamples.swift` holds the README
examples. It is compiled with the tests and never run, so it never touches
the network.
